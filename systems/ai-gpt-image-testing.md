# AI, GPT, and Fast Image Testing

AI should make the EDGE OS Brain faster at research, synthesis, ideation, asset variation, and documentation. It should not replace strategic judgment or customer truth.

## Core Principle

Use AI to increase learning velocity. Do not use AI to manufacture false certainty.

## AI Use Cases

### Research
- summarize YouTube transcripts
- extract frameworks from podcasts
- analyze competitor reviews
- cluster customer objections
- scan ad libraries manually collected by the team
- synthesize support tickets
- compare landing pages

### Copy
- generate hook variations
- rewrite by awareness stage
- create objection-handling copy
- create creator briefs
- convert customer language into scripts
- expand a winning angle into 20 variants

### Creative
- storyboard ads
- create shot lists
- generate static ad concepts
- mock product scenes
- create thumbnail/first-frame options
- write editing instructions
- create hooks by persona

### CRO
- audit PDP sections
- create landing page outlines
- map ad-to-page message match
- rewrite FAQs
- generate comparison page structure

### Operations
- convert raw notes into SOPs
- summarize RTO/support patterns
- create weekly review templates
- turn founder voice notes into briefs

## Fast Image Testing

Fast image testing means using simple mockups to test visual ideas before expensive production.

Use it for:
- first-frame tests
- product benefit statics
- comparison frames
- before/after concepts
- landing page hero directions
- packaging mockups
- creator brief examples
- offer visuals
- new product concept testing

Do not use AI images for final product claims if they misrepresent the real product.

## AI Creative Workflow

1. Start with a real customer insight.
2. Map it to awareness stage.
3. Generate 10-30 hooks.
4. Select hooks that match the product truth.
5. Create static or script variants.
6. Build simple visual mockups.
7. Test cheaply.
8. Turn winners into real shoots, creator briefs, landing page modules, or polished edits.

## Prompt Ingredients

A strong AI prompt includes:
- product
- customer
- awareness stage
- pain/desire
- product edge
- proof
- objection
- tone
- format
- constraints
- examples of good/bad output

## Multi-AI Workflow

The repo is designed to work across GPT, Claude, Grok, Cursor, and other tools.

Recommended flow:
- store raw source in `/raw/`
- use extraction prompts in `/prompts/`
- place synthesized, useful knowledge in `/wiki/`
- update canonical systems in `/systems/`
- update level playbooks only when the insight changes level-specific action
- keep source notes separate from final playbooks

## Quality Control

Reject AI output when it:
- invents metrics
- uses generic marketing language
- ignores Indian D2C realities
- makes unsupported claims
- overcomplicates the funnel
- writes copy that cannot be filmed
- creates ideas disconnected from customer language
- recommends tools before strategy

## Level-Specific AI Use

| Level | AI use |
|---|---|
| 1 | hooks, founder scripts, simple statics, customer language clustering |
| 2 | winning angle variations, creator briefs, PDP rewrites |
| 3 | creative library tagging, landing pages, competitor/review research |
| 4 | SOPs, creative ops, association planning, retention segmentation |
| 5 | portfolio synthesis, research pipelines, knowledge management, experimentation systems |

## AI Review Checklist

- Did the output use real customer language?
- Is the awareness stage clear?
- Is the product truth preserved?
- Is the claim provable?
- Can this be filmed or designed?
- Does it create variants around a real edge?
- Does it improve speed without lowering strategic quality?
